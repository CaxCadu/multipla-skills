# Sources: code-review

| Source | What it supports |
|---|---|
| [The Standard of Code Review, Google eng-practices](https://google.github.io/eng-practices/review/reviewer/standard.html), accessed 2026-11-03 | Goal of improving overall code health; approve once a change definitely improves it even if imperfect; don't approve changes that clearly worsen health; label minor points "Nit:"; facts and data outweigh opinions; style guide is the authority on style. |
| [What to look for in a code review, Google eng-practices](https://google.github.io/eng-practices/review/reviewer/looking-for.html), accessed 2026-11-03 | The checklist: design, functionality, complexity, tests, naming, comments (explain why), style, consistency, documentation. |

## Notes
- The output template, the verdict wording and the "Limits" section are this skill's own additions.
- Google's documents are written for their internal "CL" workflow; the practices are generalized here to PRs and diffs.
- Status is `draft`: a human reviewer should confirm before it becomes `reviewed`.
